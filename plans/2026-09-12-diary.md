# Diary (Capability 2 / Phase 5)

- **Date:** 2026-09-12
- **Status:** Approved
- **Requirements confirmed by user:** yes — 2026-09-12

## 1. Summary

This phase adds diary logging on top of Phase 4's Roadmap screen (see
`specs/2026-09-12-career-planner-and-diary.md`): a registered student can log
a diary entry against a specific activity from the `CheckpointPanel` (built
in Phase 4 Task 6) and optionally request AI feedback on it, on request only
— never automatically. It also adds a dedicated `/diary` screen listing all
of a student's entries chronologically, and wires the Roadmap's stats-strip
"Recent diary entries" section (a stub since Phase 4) to real data. Diary is
registered-user-only, consistent with the parent spec's gating: guests see a
locked prompt wherever diary UI would otherwise appear.

## 2. Requirements

### 2.1 Functional requirements

1. Opening `CheckpointPanel` (Phase 4) for an activity, as a registered user,
   loads and shows that activity's existing diary entries (most recent
   first) and a form to add a new one; submitting saves it via Supabase and
   it appears in the list immediately.
2. As a guest, the same panel shows a locked "Create an account to keep a
   diary" prompt instead of the entry list/form.
3. Each diary entry has a "Get AI feedback" button; clicking it calls Gemini
   (via a new `getDiaryFeedback` helper) and, once returned, displays and
   persists the feedback attached to that entry. Feedback is never generated
   automatically on entry submission.
4. The AI feedback prompt shall not comment on, assess, or provide visa,
   migration, legal, financial, or licensing advice, and shall not guarantee
   any employment or migration outcome — mirroring the existing restriction
   already applied to `getCareerReadinessAnalysis`.
5. A new `/diary` screen lists all of the signed-in student's diary entries
   across every activity, most recent first, each showing the activity
   title, entry text, timestamp, and AI feedback if present. A signed-out
   visitor sees a locked "Create an account to keep a diary" prompt linking
   to `/signup` instead of the list.
6. The Roadmap's stats strip "Recent diary entries" section (a static empty
   stub since Phase 4) shows the signed-in student's 3 most recent entries
   (activity title + entry text snippet); guests still see the Phase 4 stub.

### 2.2 Non-functional requirements

- **Sourcing/compliance surface — gate condition 2** applies to the new AI
  prompt (Task 1 below): it's a new user-facing AI-generated text surface
  and must be checked against CLAUDE.md's out-of-scope list before shipping,
  the same way a prior commit in this repo ("Keep AI career-readiness
  analysis inside its declared migration/visa scope") had to correct exactly
  this kind of drift after the fact.

### 2.3 Out of scope

- Editing or deleting a diary entry once submitted.
- Any automatic/background AI feedback generation.
- Filtering/searching the `/diary` list.

### 2.4 Assumptions

None outstanding.

## 4. Approach

Diary entries are fetched per-activity (`getDiaryEntriesForActivity`) only
when `CheckpointPanel` is open for that activity, rather than eagerly
loading every activity's entries when the Roadmap mounts — avoids N+1
queries for a screen that may have a dozen+ activities. The `/diary` screen
and the stats-strip "recent entries" section both use a separate
`getDiaryEntries(userId, { limit })` that joins `activities` for the title,
since they need entries across activities, not per-activity.

No alternative seriously considered — this follows the same
fetch-on-demand-vs-fetch-for-the-whole-list split already implicit in
`getPlanWithActivities` (one plan) vs. what this phase adds for diary
(many entries, sometimes filtered to one activity, sometimes not).

  ```js
  export async function getDiaryEntriesForActivity(activityId) {
    const { data, error } = await supabase
      .from('diary_entries').select('*').eq('activity_id', activityId)
      .order('created_at', { ascending: false })
    if (error) throw new Error(error.message)
    return data ?? []
  }

  export async function getDiaryEntries(userId, { limit } = {}) {
    let query = supabase
      .from('diary_entries').select('*, activity:activities(title)')
      .eq('user_id', userId).order('created_at', { ascending: false })
    if (limit) query = query.limit(limit)
    const { data, error } = await query
    if (error) throw new Error(error.message)
    return data ?? []
  }

  export async function createDiaryEntry(activityId, userId, entryText) {
    const { data, error } = await supabase
      .from('diary_entries')
      .insert({ activity_id: activityId, user_id: userId, entry_text: entryText })
      .select().single()
    if (error) throw new Error(error.message)
    return data
  }

  export async function setDiaryEntryFeedback(entryId, feedback) {
    const { error } = await supabase
      .from('diary_entries').update({ ai_feedback: feedback }).eq('id', entryId)
    if (error) throw new Error(error.message)
  }
  ```
